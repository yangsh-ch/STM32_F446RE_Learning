# Phase 2-03：感測器資料處理 — 加速度與陀螺儀換算成 mg／mdps

## 📊 測試總覽

| 項目 | 內容 |
| --- | --- |
| 目的 | 讀取 LSM6DS3 的加速度與陀螺儀原始資料，換算成 mg、mdps，並用已知的物理量（重力 1 g、靜止 0 dps、右手定則）驗證換算是否正確 |
| 硬體 | 沿用 [Phase 2-02](../02_I2C_LSM6DS3/02_README.md) 的接線：I2C1（PB8 = SCL、PB9 = SDA）接 GY-LSM6DS3 模組，100kHz |
| 設定 | `CTRL3_C` = 0x44（BDU、位址自動遞增）、`CTRL1_XL` = 0x40（104Hz、±2g）、`CTRL2_G` = 0x40（104Hz、250dps），每個都讀回確認（[datasheet Rev 10](https://content.arduino.cc/assets/st_imu_lsm6ds3_datasheet.pdf) Table 45～53） |
| 流程 | 等 `STATUS_REG` 的 XLDA、GDA 都是 1 → 從 `OUTX_L_G`（0x22）一次讀 12 bytes → 組成 16-bit → 換算 → 每 100 ms 印一行 |
| 輸出 | `printf` 走 ST-LINK 虛擬 COM port，**115200 baud**（連續輸出每秒約 600 字元，9600 太接近上限） |
| 量測 | Saleae Logic 2，24 MS/s；I2C Analyzer（SCL = CH0、SDA = CH1） |

## 🔍 結果

### 功能

| 測試 | 預期 | 實測 |
| --- | --- | --- |
| 設定讀回 | `config OK` | ✅ `[IMU] config OK` |
| 平放靜止 | Z ≈ +1000 mg，X、Y ≈ 0 | ✅ A ≈ (−96, +26, +1014) mg，合成 ≈ 1019 mg |
| 六個面輪流朝上 | 每軸輪流出現約 ±1000 mg | ✅ 每一軸都讀到 ±1000 mg，正負號跟模組絲印一致 |
| 靜止時的陀螺儀 | 三軸在零點偏移 ±10 dps 內（G_TyOff） | ✅ 約 +2.2／−2.7／−0.3 dps，各方向都一樣 |
| 用手轉動 | 逆時針（從 +軸尖端看）為正 | ✅ X、Y、Z 都是逆時針為正、順時針為負（右手定則） |
| 邏輯分析儀 | 一筆 12-byte 讀取，手動換算跟終端機一致 | ✅ 6 軸都一致 |

終端機輸出（平放靜止）：

```
[IMU] config OK
A[mg]     31    -61   1019  G[mdps]    2205   -2668    -315
A[mg]     33    -61   1019  G[mdps]    2310   -2651    -175
```

- `A[mg]`：加速度 X、Y、Z，單位 mg（1 g = 1000 mg ≈ 9.8 m/s²），原始值 × 0.061
- `G[mdps]`：角速度（繞 X、Y、Z 軸），單位 mdps（1000 mdps = 1 dps），原始值 × 8.75

### 六面測試（各方向取平均）

| 軸 | 朝上 | 朝下 | 零點偏移（上＋下）÷ 2 | 靈敏度檢查（上－下）÷ 2 |
| --- | --- | --- | --- | --- |
| X | +1009.4 | −982.2 | +13.6 mg | 995.8 mg |
| Y | +989.5 | −1006.1 | −8.3 mg | 997.8 mg |
| Z | +1013.6 | −986.2 | +13.7 mg | 999.9 mg |

- 零點偏移都在 datasheet 的 ±40 mg（LA_TyOff）以內
- （上－下）÷ 2 都在 1000 mg 的 0.5% 以內，代表 0.061 mg/LSB 的換算正確
- 軸垂直時，擺放歪幾度對該軸影響很小（歪 5° 只差約 4 mg），所以用手扶著量就可以

### 轉動測試

| 軸 | 逆時針 | 順時針 | 交叉確認 |
| --- | --- | --- | --- |
| X | ✅ 正 | ✅ 負 | 加速度計的重力路徑方向相反 |
| Y | ✅ 正 | ✅ 負 | 加速度計的重力路徑方向相反 |
| Z | ✅ 正 | ✅ 負 | 只有陀螺儀（Z 朝上時重力不會轉） |

- Z 順時針有一行 −286702 mdps（原始值 −32766），接近 16-bit 下限，可能已飽和

### 邏輯分析儀：12-byte 讀取的手動換算

線上序列：`S → [0x6B]W → 0x22 → Sr → [0x6B]R → 12 個 byte（前 11 個 ACK、最後一個 NA）→ P`

| 軸 | 線上順序（L, H） | 組成 16-bit | 原始值 | × 靈敏度 | 終端機靜止時的範圍 |
| --- | --- | --- | --- | --- | --- |
| GX | F6, 00 | 0x00F6 | +246 | 2152 mdps | 1461～2642 |
| GY | D3, FE | 0xFED3 | −301 | −2633 mdps | −1338～−3946 |
| GZ | E1, FF | 0xFFE1 | −31 | −271 mdps | −175～−420 |
| AX | 08, 02 | 0x0208 | +520 | 31 mg | 30～38 |
| AY | 08, FC | 0xFC08 | −1016 | −61 mg | −61～−66 |
| AZ | 67, 41 | 0x4167 | +16743 | 1021 mg | 1017～1021 |

- 擷取時已停掉 COM port 監聽，比對的是模組靜止時的讀值範圍
- AY 實際是 −61.98 mg，程式顯示 −61：C 的整數除法往 0 捨去

## ✅ 結論

- 換算正確：三軸靈敏度在 0.5% 以內，加速度零點偏移 +13.6／−8.3／+13.7 mg、陀螺儀約 +2.2／−2.7／−0.3 dps，都在 datasheet 典型值內
- 位元組順序（低位在前）、二補數、正負號（右手定則）都用實測確認
- **量測技巧**：
  - 用陀螺儀判斷模組有沒有靜止：靜止時 G 穩定在零點偏移附近，手一晃就跳到數萬 mdps
  - 六面法：（上＋下）÷ 2 抵銷擺放傾斜得到零點偏移，（上－下）÷ 2 驗證靈敏度
  - 繞水平軸轉時，可以用加速度計的重力路徑交叉確認陀螺儀方向；繞垂直軸轉時只能靠陀螺儀
- **限制**：
  - 零點偏移還沒扣除，靜止時陀螺儀仍讀到 2～3 dps；之後要積分角度前要先校正
  - ±250 dps 量程，快速轉動時會飽和
  - 整數換算往 0 捨去，誤差小於 1 mg／1 mdps

## 💡 學到的關鍵概念

| 重點 | 做法與結果 |
| --- | --- |
| 用已知物理量驗證感測器 | 以重力 1 g、靜止 0 dps、右手定則為基準；六面法算出零點偏移（≤ 14 mg）與靈敏度誤差（< 0.5%） |
| 從線上 byte 追到換算結果 | 邏輯分析儀擷取 12-byte burst，手動做低位在前、二補數、靈敏度換算，6 軸都與韌體輸出一致 |
| 依 datasheet 設定並讀回確認 | BDU 避免高低 byte 拼錯、IF_INC 讓 6 軸一次讀完；寫入會覆蓋整個 byte，所以 `CTRL3_C` 寫 0x44 保留 IF_INC |
| 量程與解析度的取捨 | ±2 g 換到 0.061 mg/LSB；±250 dps 手轉夠用，快轉會飽和（實測原始值 −32766） |
| 抓出 datasheet 的陷阱 | `FS_XL` 01 是 ±16 g 不是 ±4 g；`BW_XL` 預設不生效，104 Hz 實際頻寬 50 Hz；開機 ODR 為關閉 |

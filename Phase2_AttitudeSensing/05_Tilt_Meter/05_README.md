# Phase 2-05：Tilt Meter — 加速度計傾斜角與 OLED 水平儀

## 📊 測試總覽

| 項目 | 內容 |
| --- | --- |
| 目的 | 用加速度計算出模組的傾斜角度（Roll／Pitch），在 OLED 上同時顯示數字和泡泡水平儀，做成不用接電腦也能用的傾斜計；按 USER 按鈕把目前姿勢設成 0°；再用六面擺放和 iPad 量測驗證角度 |
| 硬體 | 接線與 [Phase 2-04](../04_Sensor_OLED/04_README.md) 完全相同：OLED 走 SPI（PA_7 MOSI／PA_5 SCLK／PB_10 CS／PB_1 DC／PB_0 RES，MISO 指定 PA_6 不接線），IMU 走 I2C1（PB8 = SCL、PB9 = SDA）；USER 按鈕為板上的 PC13 |
| 角度公式 | roll = atan2(ay, az)，pitch = atan2(−ax, √(ay² + az²))；與 [`tools/attitude_viewer.html`](../tools/README.md) 的 A 模式相同 |
| 歸零 | 按下 USER 時中斷函式只設旗標；主迴圈看到旗標才把當下的絕對角度存成參考值。顯示值 = 絕對角度 − 參考值，Roll 再包回 (−180°, 180°] |
| 流程 | 開機：OLED 初始化 → 8MHz 設定 → 清屏 → 設定 IMU → 畫標題和 Ref。之後每圈：等資料就緒 → 讀 12 bytes → 算角度 → UART 印一行 → 重畫 R／P 兩行和泡泡圖 → sleep 50 ms |
| 輸出 | `printf` 走 ST-LINK 虛擬 COM port，115200 baud；每行 `Roll … Pitch …  A[mg] …`，按 USER 時多印一行 `[TILT] zero set: roll … pitch …`（印的是絕對角度） |
| 量測 | Saleae Logic 2，24 MS/s；D0／D1 = SCL／SDA，D2 = SCLK，D3 = CS，D4 = MOSI，D5 = DC；角度對照用 iPad 的 phyphox「傾斜」實驗 |

### OLED 畫面

左半邊 64 px 放數字（每行 10 個字），右半邊 64 × 64 px 放泡泡水平儀：

```
TILT [deg]  │     ╭─────────╮
            │   ╱   ╭───╮    ╲
R    -63.6  │  │    │ ● │     │
P    -29.5  │  │    ╰───╯     │
            │   ╲            ╱
Ref (USER)  │     ╰─────────╯
R      1.0  │
P    -37.9  │
```

| 元素 | 說明 |
| --- | --- |
| 外圈 r = 30 px | 滿刻度 30°；泡泡中心最遠 26 px，剛好碰到外圈（每度 0.867 px） |
| 內圈 r = 9 px | 約 10°（10 × 0.867 = 8.7 px） |
| 四個刻度 | 外圈內側 3 px，標出軸向 |
| 泡泡 r = 4 px | 往**高的那一側**移動，跟真的水平儀一樣；超過 30° 時停在外圈上，方向不變 |
| 擺法 | 模組正面朝上、+X 朝 OLED 上方，所以 +Y 朝左（右手定則）：+X 端抬高 → 泡泡往上，+Y 端抬高 → 泡泡往左 |
| Ref 兩行 | 只在開機和按 USER 時重畫，不是每圈都送 |

### 六面擺放（UART 讀值，未歸零）

| 朝上 | 預期 Roll／Pitch | 實測 Roll／Pitch | A [mg] | 偏離該軸的角度 |
| --- | --- | --- | --- | --- |
| +Z | 0／0 | −3.6／−2.0 | 36, −63, 1021 | 4.1° |
| −Z | ±180／0 | 179.9／8.9 | −152, 1, −969 | 8.9° |
| +Y | +90／0 | 82.5／0.1 | −2, 984, 129 | 7.5° |
| −Y | −90／0 | −90.4／−1.8 | 31, −1007, −7 | 1.8° |
| +X | 不穩定／−90 | −7.6（−6.5 到 −8.8）／−85.5 | 1011, −10, 78 | 4.4° |
| −X | 不穩定／+90 | 171（170.3 到 173.1）／84.5 | −982, 14, −94 | 5.5° |

- 用 UART 印的 A[mg] 手算：±Z、±Y 四面與板子印的相差 0.1° 以內；±X 兩面的 Roll 差 0.3–0.4°（+X 手算 −7.3°、−X 手算 171.5°）
- ±X 的差異在 mg 取整數的範圍內：`raw_to_mg()` 會捨去小數，Y、Z 只有幾十 mg 時，1 mg 的差就影響約 0.7°；把 Y、Z 各加上 0～0.999 mg 重算，+X 的 Roll 在 −8.03° 到 −7.21° 之間，−X 在 170.93° 到 171.62° 之間，板子印的值都在範圍內
- **偏離該軸的角度**：另外兩軸合起來與朝上那一軸的夾角，例如 +Y 那面 Z = 129 mg，atan(129 / 984) = 7.5°，所以 Roll = 90 − 7.5 = 82.5
- 不是剛好 0／±90／180，是因為每一面的另外兩軸還有 30–150 mg，重力沒有完全落在朝上那一軸
- **±X 兩面 Roll 跳約 2–3°**：X 朝上時 Y、Z 只剩約 80–95 mg，Roll 只由這兩軸算，雜訊佔的比例變大；+Z 那面只跳 0.1°
- −Z 那面是手拿著倒轉，Y 在 −19 到 47 mg 之間跳，所以 Roll 在 177.2 到 −178.8 之間變動；其他五面放在桌上

### 與 iPad 比對（phyphox「傾斜」，模組用紙膠帶貼在 iPad 螢幕角落）

兩邊都用「抬起後讀數 − 平放讀數」：

| 測試 | 模組 | iPad | 差 |
| --- | --- | --- | --- |
| 抬上緣（Pitch） | −1.8 → −44.5：**42.7°** | up/down −0.39 → 43.18：**43.6°** | 0.9° |
| 抬側邊（Roll） | −0.8 → −53.2：**52.4°** | left/right 0.52 → 52.54：**52.0°** | 0.4° |

- 另一軸幾乎不動：抬上緣時模組 Roll 變 0.1°、iPad left/right 變 0.24°；抬側邊時模組 Pitch 變 0.5°、iPad up/down 變 1.3°
- 三筆的 A[mg] 手算也都與板子印的相同：平放 (32, −14, 1020) → −0.8／−1.8，抬上緣 (719, −11, 732) → −0.9／−44.5，抬側邊 (23, −815, 609) → −53.2／−1.3

### 時序（[`captures/20261111_timing.sal`](captures/20261111_timing.sal)，52 個迴圈）

用 2-04 的 [`tools/timing.py`](../04_Sensor_OLED/tools/timing.py) 分析：

| 項目 | 預估 | 實測 |
| --- | --- | --- |
| I²C 讀取（4 個 START） | 約 1.8 ms | 1.792 ms |
| OLED 更新（758 byte） | 約 6 ms | **6.330 ms** |
| 一圈忙碌時間（I²C 開始 → SPI 結束） | — | 8.261 ms |
| 迴圈週期 | 約 58–60 ms | **58.003 ms**（約 17 Hz） |

- 52 個迴圈之間的差異都在 0.01 ms 以內
- **758 byte 的組成**：數字兩行共 20 個字，每字 12 byte（6 個指令、6 個像素）= 240 byte；泡泡圖 6 個設定視窗的指令 + 512 byte 像素。指令共 126 byte，與實測相同
- 預估用的是 2-01 擷取量到的每 byte 8.0 µs（雙線、8MHz）；這次用「OLED 更新時間 ÷ byte 數」算，平均每 byte 8.35 µs
- 泡泡圖 512 byte 像素只要 6 個指令；如果用畫字的方式（每 6 byte 像素重設一次游標）送同樣的像素，會變成約 1024 byte

## 🐛 問題與根因

| # | 現象 | 根因 | 解法 |
| --- | --- | --- | --- |
| ① | 抬高 iPad 遠端，泡泡往右跑，不是往上 | 程式假設 +X 朝螢幕右邊，實際擺法是 +X 朝 OLED 上方，方向差 90° | 改成 bx = −roll、by = pitch；實測抬遠端往上、抬右邊往右 ✅ |
| ② | 手機比對時，一組差約 1°、另一組差約 10°，換一組又差約 5° | 模組貼在尺上、尺和手機只是疊著放，抬起時兩者角度不一定相同；也沒有記錄平放時的起點，兩邊都含各自沒放正的偏差 | 模組用紙膠帶貼在 iPad 螢幕角落，先記平放讀數再相減；兩軸都在 1° 以內 |

## ✅ 結論

- 只用加速度計的傾斜角與 iPad 比對，兩軸誤差都在 1° 以內，靜止雜訊 ±0.1°
- X 軸越接近垂直，Roll 越不準：±X 朝上時 Roll 跳 2–3°，這是公式本身的限制
- 泡泡圖用 64 × 64 的畫布整塊送，OLED 更新 6.33 ms，比 2-04 只畫文字的 6.97 ms 還短
- 迴圈 sleep 從 100 ms 縮到 50 ms，週期 58.0 ms，泡泡約每秒更新 17 次

## 💡 學到的關鍵概念

| 重點 | 做法與結果 |
| --- | --- |
| 用重力算傾斜 | atan2 只需要比例，原始值不用先換成 mg；Pitch 的分母用 √(ay² + az²)，範圍固定在 ±90° |
| 公式的限制 | Roll 只由 Y、Z 算，X 接近垂直時這兩軸變小，雜訊造成的角度誤差變大 |
| 中斷只設旗標 | ISR 不讀感測器也不 printf，只設一個 `volatile` 旗標，主迴圈下一輪再處理 |
| 比對要有共同起點 | 量測物要固定在一起，並記下起點讀數再相減，才能把兩邊各自沒放正的偏差消掉 |
| 畫布 + 視窗寫入 | 先在 RAM 畫好 64 × 64 px，再用 0x21／0x22 把 OLED 寫入範圍限制在這一塊，512 byte 連續送完 |
| 中點圓演算法 | 只算 1/8 圓弧的整數座標，再對稱畫到其他七段；實心圓用 dx² + dy² ≤ r² + r，小半徑比較圓 |
| 座標要照實際擺法 | 螢幕的上下左右要對應模組實際的軸向；這次就是假設錯軸向，泡泡方向差 90° |
| 先預估再量測 | 從送法推算 758 byte、約 6 ms，實測 6.33 ms，byte 數完全相同 |
